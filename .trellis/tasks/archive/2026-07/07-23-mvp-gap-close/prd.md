# MVP 缺口收口

## Goal

一小轮打磨正式前端的**状态闭环**：档案保存、会话回看、本机重置、后端不可达时的反馈连贯一致，走查不「假成功 / 假空白」。

## Background

本地联调已通。本轮不做记忆加强或安全评测，只修前端联调里会误导用户的状态断点：

- 设置页重置先删 `client_id` 再 `save`，提示与真实换号时机不一致。
- 历史进聊天、侧栏换伙伴等路径存在失败被吞。
- hydrate 网络失败时用户可能不知道后端未启动。

## Requirements

| ID | 需求 | 说明 |
|----|------|------|
| R1 | 历史回看 | 从会话历史进入聊天：加载中 / 成功填消息 / 失败人话说明；成功后 `sessionId` 与列表一致 |
| R2 | 本机重置 | 重置后轮换本机标识、清空当前会话意图，档案回到默认；**强制 `location.reload()`**；提示与行为一致 |
| R3 | 写路径可见失败 | 模式切换、聊天侧栏换伙伴等写后端失败时用人话提示，禁止静默成功态 |
| R4 | 后端不可达（轻量） | 首次 hydrate 因网络失败时，在壳层或首页给出可理解提示（不做完整错误总线） |

## Out of scope

- 记忆抽取/摘要加强
- 安全词库加厚与抽检基线
- Docker / 登录 / 家长 / 语音 / 第二套皮肤
- 大改 `demo/`
- 全局 toast / 错误总线重构
- 变更后端 API 合同

## Acceptance Criteria

- **AC1**：历史列表点开某会话 → 聊天页展示该会话消息；失效 `session` 有人话错误，不空白假装成功。
- **AC2**：确认重置后页面刷新；新 `jiuban_client_id` 生效；聊天为空、档案为默认；文案不再写「稍后才换标识」类矛盾句。
- **AC3**：后端关闭时，设置里切模式或聊天侧栏换伙伴出现人话失败提示。
- **AC4**：后端关闭时冷启动前端，用户能看到「连不上服务器」类提示。
- **AC5**：不改后端 API；不新增登录/部署能力。
