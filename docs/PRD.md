## 1. 背景与目标

### 1.1 背景

多数开源聊天项目（LibreChat、Open WebUI、LobeChat）默认服务**开发者与知识工作者**：多模型切换、RAG、插件、自托管配置。普通人打开后面对的是「API Key、温度、Endpoint」，门槛高，也缺少「有人陪我聊聊」的感觉。

与此同时，小孩与大量普通成年人真正需要的是：

- 有耐心听我说完
- 说话好懂、语气友好
- 记得我是谁、我喜欢什么
- 能陪聊天、讲故事、解闷、给一点情绪支持
- **对小孩尤其安全**：不诱导危险行为、不当内容可拦截、家长可管

本产品不以「第二个 ChatGPT 工作台」为目标，而以**陪伴服务**为核心价值。

### 1.2 产品愿景

> 做一个温暖、好懂、开箱即用的 AI 陪伴伙伴：  
> 小孩可以安心聊天、听故事、问「为什么」；  
> 普通人可以倾诉日常、解闷、获得轻松友好的回应。  
> 技术能力藏在背后，用户感受的是「陪着我的朋友」，而不是「复杂的 AI 工具」。

### 1.3 产品原则

1. **陪伴优先，工具其次**：默认不做生产力功能堆砌
2. **零门槛**：普通用户不需要理解模型、密钥、参数
3. **安全底线不可破**：儿童模式默认最严；成人模式也需拒答有害内容
4. **温暖但不越界**：鼓励表达与陪伴，不替代真人关系，不制造病态依赖话术
5. **记得你**：适度记住称呼、喜好、近期话题，让对话有延续感

### 1.4 成功标准（MVP 上线后 4 周）

- 新用户 **1 分钟内**完成首次对话（无需配置 API）
- 核心路径（打开 → 选/跳过人设 → 聊天 → 回看历史）成功率 ≥ **99%**
- 儿童模式下，抽样有害/越界提示的拦截率达到内部安全用例基线（见第 5.5 节）
- 用户主观反馈中，「愿意再聊」「感觉被认真对待」占比可作为早期北极星指标之一

## 2. 用户与场景

### 2.1 目标用户

| 角色 | 描述 | 核心诉求 | 使用约束 |
|------|------|----------|----------|
| **儿童用户** | **小学生为主（约 6–12 岁）** | 聊天、听故事、问百科、一起玩「假想游戏」 | 儿童模式；内容过滤；家长同意流程二期再做 |
| **家长 / 监护人** | 为孩子开通并管理使用 | 安全、时长、话题可控；自己也能简单会用 | 完整家长面板与同意流程：**二期及以后** |
| **普通成年人** | 非技术用户，需要情绪陪伴与日常闲聊（含轻度树洞倾诉） | 好说话、不说教、记得我、随时能聊 | 成人陪伴模式；**不做恋爱角色**；语气成熟但仍守安全边界 |

**明确非首要用户**：开发者、企业知识库管理员、需要多模型对比的重度 AI 用户（其需求仅作为后台能力，不对 C 端暴露）。

### 2.2 核心场景

1. **睡前 / 闲暇陪伴**：小孩说「今天好无聊」→ 伙伴提议聊天话题、小游戏或短故事  
2. **听我说说**：普通人倾诉工作/生活小烦恼 → 先共情再温和回应，避免机械说教  
3. **好奇问答**：小孩问「为什么天是蓝的」→ 用年龄适配的语言解释，可追问  
4. **角色扮演陪伴**：选「小狐狸朋友 / 温柔学长 / 幽默搭子」等人设后持续用该人设聊天  
5. **记得我**：下次打开会打招呼提到昵称或上次聊过的兴趣（在隐私允许范围内）  
6. **家长安心**（二期）：同意流程、使用时长、宵禁等——一期不做登录与家长同意，仅靠儿童模式 + 安全策略

### 2.3 非目标（明确不做 / 暂缓）

- 对用户暴露「多模型切换、Temperature、Endpoint」等专业配置（仅管理员后台）
- 文档知识库 / 企业 RAG / MCP 工作台（与陪伴主线无关，技术栈可预留但不做产品入口）
- 替代心理咨询、医疗诊断、学习成绩保证等承诺
- **恋爱角色 / 恋爱养成**（明确不做；成人仅允许友好陪伴与轻度树洞倾诉，避免暧昧玩法）
- 儿童不可接触的情感玩法、过度暧昧话术
- **登录 / 账号体系**（一期不做；二期再议手机号与家庭账号）
- **家长同意流程**（接受服务小学生，同意流程可后面做）
- 微信小程序 / 原生 App（一期仅 Web；后续再扩展）
- 第三方内容审核 API（一期不做；二期可接）
- 复杂 Agent 编排、代码解释器、Artifacts 生产力套件（首版不做）

## 3. 定位对比与取舍

开源项目解决「怎么聊得上、怎么接模型」；本产品解决「谁来陪、怎么陪得安全、好懂」。

| 能力域 | 开源常见做法 | 本产品（陪伴向）取舍 |
|--------|--------------|----------------------|
| 多模型 UI | 顶栏切换 GPT/Claude/Ollama | **对用户隐藏**；后台统一模型 |
| 系统提示词 | 用户自写 | **产品化人设 / 陪伴角色**，用户一键选择 |
| 语音 | 二期能力 | **陪伴场景优先级提高**（二期 P0） |
| 长期记忆 | 少见或弱 | **MVP 即做轻量记忆**（昵称、喜好、禁忌） |
| RAG / 文件 | 核心卖点 | **降级**：非主路径；百科可用检索增强可选 |
| 安全与儿童 | 通常弱 | **儿童模式 + 内容安全 = 一等公民** |
| UI 气质 | ChatGPT 工作台 | **卡通温暖皮肤（一期）**；预留成人中性皮肤（二期）；大字号、低信息密度、Web 移动优先 |

**差异化一句话**：不是「更强的 AI 工具」，而是「更好懂、更安心的聊天伙伴」。

## 4. 产品范围与版本规划

### 4.1 MVP（一期，建议 4–6 周）

**必须有（P0）**

- 移动优先的陪伴聊天界面（大气泡、清晰头像/角色形象、少按钮）
- 流式回复 + 口语化中文（避免大段 Markdown 堆砌；儿童模式默认短句）
- **陪伴人设**：至少 2–3 个官方角色（如：温柔陪伴型、活泼玩伴型、耐心讲解型）
- **模式切换**：儿童模式 / 成人模式（儿童模式默认更短回复、更严安全、更浅话题）
- **轻量记忆**：昵称、年龄段（可选）、喜欢的称呼、近期 3–5 条偏好摘要
- 会话历史（本地设备可回看；无登录同步）
- **内容安全（一期）**：**系统提示词约束 + 规则词库** 拦截有害/色情/暴力/自伤/危险挑战等，并温和转话题
- **卡通视觉皮肤**（亮色、角色化、避免冷冰冰工作台风）
- 错误提示用人话（「现在有点忙，稍后再试」而非 API 500）
- 后端统一接入 LLM（OpenAI 兼容即可）；**用户零配置、零登录**
- **Web 移动优先**页面，浏览器即可用

**应该有（P1）**

- 开场引导（今天想聊什么？听故事？问问题？）
- 一键话题卡片（「听个故事」「说说今天」「脑筋急转弯」）
- 消息重新生成 / 停止
- 儿童 / 成人模式本地开关（无家长口令流程亦可先用）

**可以延后（P2）**

- 语音输入输出
- 成人中性温暖皮肤（与卡通并列的第二套）
- 家长同意流程、家长口令、完整管控面板
- 登录 / 多设备同步
- 恋爱以外的更多角色玩法扩展
- 图片理解（给画看一看）
- 第三方内容审核 API

### 4.2 二期

- **语音陪伴**（按住说话 / 朗读回复）——对小孩与普通人更友好
- **家长同意流程** + 家长面板（时长、宵禁、对话可见性）
- 第二套 **中性温暖皮肤**（成人向）
- 登录与家庭账号（便于多设备与管控）
- 更强长期记忆与「今日心情」轻量打卡
- 安全故事库 / 官方话题包；可选接入第三方审核 API
- 可选联网百科（仅成人或家长开启）

### 4.3 三期

- 多端（微信小程序 / App）
- 更丰富角色与轻度互动玩法（**仍不做恋爱养成**，除非产品另行决议）
- 情绪趋势洞察（给家长的周报，注意隐私与误用风险）

## 5. 功能需求详述

### 5.1 陪伴对话核心

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| CMP-01 | 打开即可聊 | P0 | 无需填写 Key；进入即有角色与输入框 |
| CMP-02 | 流式回复 | P0 | 边生成边显示；可停止 |
| CMP-03 | 口语化回复风格 | P0 | 系统提示约束：短句、少术语；儿童模式更短 |
| CMP-04 | 话题卡片引导 | P1 | 空状态展示 ≥3 个可点话题 |
| CMP-05 | 共情优先策略（含轻度树洞） | P0 | 倾诉类输入先回馈情绪再给建议；允许日常烦恼倾诉（评测用例通过） |
| CMP-06 | 不替代专业帮助 | P0 | 涉及自伤/暴力/虐待等：安抚 + 引导求助真人/热线，不深入危险细节 |
| CMP-07 | 不做恋爱角色 | P0 | 无恋爱人设入口；回复避免恋爱养成/暧昧玩法导向 |

### 5.2 人设与模式

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| PER-01 | 官方陪伴角色 ≥3 | P0 | 角色名、头像、简介、专属系统提示可切换 |
| PER-02 | 儿童 / 成人模式 | P0 | 模式影响回复长度、词汇、安全策略强度 |
| PER-03 | 角色一致性 | P0 | 同会话内人设不漂移（抽检） |
| PER-04 | 自定义人设 | P2 | 用户可填简短设定（成人模式；儿童需家长允许） |

### 5.3 记忆与连续性

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| MEM-01 | 基础档案 | P0 | 可设置昵称；对话中可正确称呼 |
| MEM-02 | 偏好摘要 | P0 | 用户说过的喜好可在后续自然提及 |
| MEM-03 | 记忆可查看/删除 | P1 | 用户或家长可清除记忆 |
| MEM-04 | 跨会话记忆 | P1 | 新会话仍保留档案级记忆（非全文历史硬塞） |

### 5.4 会话与界面

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| UI-01 | Web 移动优先布局 | P0 | 手机浏览器下单手可完成发送；桌面亦可打开 |
| UI-02 | 历史会话（本地） | P0 | 同设备可回看；无账号云同步 |
| UI-03 | 卡通皮肤 + 大字号 | P0 | 一期默认卡通视觉；儿童模式字号更大 |
| UI-04 | 专业配置入口隐藏 | P0 | 普通用户界面无模型/温度等控件 |
| UI-05 | 第二套中性皮肤 | P2 | 与卡通皮肤可切换（二期） |
| UI-06 | 语音输入输出 | P2（二期 P0） | 可语音说、可朗读回 |

### 5.5 安全与家长可控（关键）

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| SAF-01 | 提示词安全约束 | P0 | 系统提示含分龄安全规则；抽检越界请求被拒或转话题 |
| SAF-02 | 规则词库过滤 | P0 | 输入/输出命中词库时拦截或改写；词库可配置更新 |
| SAF-03 | 儿童模式加强 | P0 | 色情、血腥、恐怖、危险实验、隐私套取等默认拦截 |
| SAF-04 | 不索取敏感隐私 | P0 | 不主动要住址、学校全名、证件号等 |
| SAF-05 | 家长同意流程 | P2 | 首次儿童使用需监护人确认（二期） |
| SAF-06 | 家长口令 / 宵禁 / 时长 | P2 | 完整管控面板（二期） |
| SAF-07 | 第三方审核 API | P2 | 预留接口；一期不强制接入 |

## 6. 人设与对话策略（产品规格）

### 6.1 官方角色示例（可改名）

| 角色 | 适合 | 气质 | 典型开场 |
|------|------|------|----------|
| 小暖 | 小孩 / 需要温柔的人 | 耐心、鼓励、会讲短故事 | 「我在呀，今天想聊点什么？」 |
| 跳跳 | 小孩 | 活泼、爱提问、爱小游戏 | 「要不要来个脑筋急转弯？」 |
| 老张 / 阿茶 | 普通人 | 稳重听友、少说教 | 「我听着呢，你慢慢说。」 |

### 6.2 回复规范（写入系统提示与评测）

- 儿童模式：单次回复建议控制在较短篇幅；少生僻词；多用比喻
- 成人陪伴：允许轻度树洞倾诉；先情绪确认，再给可选建议；避免「你应该」连发
- 禁止：恐吓、羞辱、诱导秘密对抗家长、宣扬自伤；**禁止恋爱养成/暧昧导向**（尤其儿童一律禁止）
- 遇到不会的问题：诚实说不确定，可建议问家长/老师

## 7. 非功能需求

| 类别 | 要求 |
|------|------|
| 体验 | 首屏信息少；主操作不超过「输入 + 发送」；加载有陪伴感动效（轻量） |
| 性能 | 首 token 尽量快；弱网有明确等待反馈 |
| 渠道 | **一期仅 Web**（移动优先 H5，兼顾桌面浏览器） |
| 隐私 | 无登录；数据尽量留本地/匿名会话；记忆可删；默认最小化采集 |
| 安全合规 | 一期 = 提示词 + 规则词库；词库可热更新；预留二期第三方审核 |
| 可访问性 | 足够字号、可点区域大；二期考虑朗读 |

## 8. 信息架构与关键交互

### 8.1 页面结构（C 端）

```
┌─────────────────────────────────────┐
│  角色头像 + 名字     [儿童/成人模式] │
├─────────────────────────────────────┤
│                                     │
│         温暖气泡对话流               │
│         （可点话题卡片）             │
│                                     │
├─────────────────────────────────────┤
│  [话题]  输入「想说点什么…」  [发送] │
└─────────────────────────────────────┘
```

侧栏会话列表对儿童可弱化；成人可保留「以前的聊天」。

### 8.2 交互原则

- 少设置、少术语、少二级菜单
- 用话题卡片降低「不知道说什么」的启动成本
- 错误与安全拦截都用温和、不恐吓的文案
- Enter 发送在手机上以按钮为主；桌面可保留快捷键

## 9. 技术架构建议（服务陪伴产品，对用户不可见）

> 工程上仍可借鉴开源 Chat UI 的流式对话与会话存储；产品层必须包一层「人设 / 记忆 / 安全」。

```
用户端（温暖 UI）
    │
    ▼
陪伴 BFF
    ├─ 人设与模式（儿童/成人）注入 System Prompt
    ├─ 记忆检索（档案 + 摘要）
    ├─ 安全过滤（提示词约束 + 规则词库，输入前 / 输出后）
    └─ Chat Service → LLM Provider（统一配置）
         │
         └─ Session Store（无账号：本地 / 匿名会话 + 记忆）
```

**MVP 技术取舍**：Web + 卡通 UI + 人设 + 词库安全；不做登录、不做 RAG、不接第三方审核；把人力给人设质量与陪伴体验。

## 10. 数据模型（概念）

- **Profile（本地/匿名档案）**：device_id 或 anonymous_id、昵称、模式（child/adult）、年龄段（可选）；一期无家长绑定
- **Companion（角色）**：id、name、avatar、system_prompt、tone_rules；**不含恋爱类角色**
- **Memory**：key-value 或短摘要（昵称、喜好、禁忌、最近话题）
- **Session / Message**：同通用聊天；可标记 safety_action（放行/拦截/改写）
- **SafetyLexicon（规则词库）**：category、terms、action（block/rewrite）、mode_scope（child/adult/all）
- **ParentSettings**（二期）：口令、同意状态、时长上限、宵禁

## 11. 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| 儿童安全事故 / 不当内容 | 信任崩塌、合规风险 | 儿童模式最严；提示词+词库双端过滤；人工抽检；家长同意二期补齐 |
| 无登录导致换机丢数据 | 体验抱怨 | MVP 接受；文案提示「数据在本机」；二期登录同步 |
| 过度情感依赖 | 舆论与伦理风险 | 产品文案强调「AI 伙伴不是真人」；鼓励线下关系 |
| 把陪伴做成说教工具 | 用户流失 | 共情优先；评测倾诉场景 |
| 模型胡编吓到小孩 | 体验差 | 儿童模式降低玄学/恐怖话题；不确定就承认 |
| 范围漂回「万能 ChatGPT」 | 失去陪伴差异化 | 功能评审以「是否增强陪伴感」为门槛 |

## 13. 验收清单（MVP）

- [ ] 浏览器打开即可聊，**无需登录、无需配置 API**
- [ ] 默认 **卡通皮肤**；至少 2 个官方角色可切换且语气可区分（无恋爱角色）
- [ ] 儿童模式与成人模式行为可区分（回复风格 + 安全强度）
- [ ] 成人模式支持轻度树洞倾诉（共情优先评测通过）
- [ ] 设置昵称后，伙伴会正确称呼（本地档案）
- [ ] 安全：提示词约束 + 规则词库；暴力/色情/自伤/危险挑战/套取隐私等用例按策略处理
- [ ] 手机 Web 可流畅完成一轮完整对话
- [ ] 界面无模型/API 等专业配置暴露给普通用户

## 15. 界面 Demo（对照本 PRD）

本地打开 **`demo/index.html`**。当前为 **产品壳** 对照（非讲解 Tour）：不接真实大模型，用剧本与模拟流式演示体验。正式交付见 `frontend/` + `backend/`（[`directory-structure.md`](./directory-structure.md)）。
